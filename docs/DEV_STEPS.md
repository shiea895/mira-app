# 開発手順書（第2版）

[SPEC.md](./SPEC.md) の仕様をもとに、小さなステップに分解した開発手順。

> **第2版での変更点**：開発方針を「個人利用版をまず完成させる」に変更。ステップ1〜13（画面の基本機能）は従来通り実施済み。元のステップ14〜20（Firebase導入・ログイン・家族共有）は、個人利用版が一段落するまで**保留**とし、[家族共有を追加する時のステップ（保留中）](#家族共有を追加する時のステップ保留中)にまとめて移動した。個人利用版の仕上げは新ステップ14〜16として再構成している。

---

ステップ1: 開発環境の準備
- やること: Node.js、コードエディタ（VSCode）、Gitなど開発に必要なツールをインストールする。プロジェクト用の作業フォルダ構成（`docs/`, `src/` など）を決める。
- 完成の目安: エディタでプロジェクトフォルダを開け、ターミナルでコマンドが実行できる状態になっている。

ステップ2: プロジェクトの雛形作成
- やること: `index.html` / `style.css` / `script.js` の空ファイルを作成し、ブラウザで「Hello, 買い物リスト」のような文字だけ表示できる最小構成を作る。
- 完成の目安: ブラウザでファイルを開く（またはローカルサーバー経由）と、想定した文字が画面に表示される。

ステップ3: 共通レイアウト（ヘッダー・下部ナビ）の作成
- やること: 全画面共通で使うヘッダー（アプリ名・設定アイコン）と下部ナビゲーション（ホーム／買い物リスト／設定）のHTML・CSSを作成する。中身の切り替えはまだ不要。
- 完成の目安: ヘッダーと下部ナビが画面に固定表示され、見た目がスマホサイズで崩れていない。

ステップ4: S2ホーム画面の静的UI（ダミーデータ表示）
- やること: 仕様書S2の通り、アイテムカード一覧（アイコン枠・名前・在庫状態バッジ）をダミーデータ（JS配列にハードコード）で数件表示する。
- 完成の目安: カテゴリ見出し付きでダミーアイテムが一覧表示される。

ステップ5: カテゴリタブでの絞り込み機能
- やること: S2上部にカテゴリタブ（すべて／食品／日用品など）を作り、タップでダミーデータの表示を絞り込む処理をJavaScriptで実装する。
- 完成の目安: タブを切り替えると表示されるアイテムが正しく絞り込まれる。

ステップ6: 在庫状態のワンタップ切替
- やること: アイテムカードをタップすると「在庫あり⇔買う」の状態バッジが切り替わる処理を実装する（この時点ではまだ保存されず、リロードで消えてよい）。
- 完成の目安: タップするたびに状態表示が正しく切り替わる。

ステップ7: S4アイテム登録・編集画面の静的UI
- やること: 名前入力欄、カテゴリ選択、在庫状態トグル、メモ欄、保存／キャンセルボタンを持つ画面を作成する。S2の「＋」ボタンから遷移できるようにする。
- 完成の目安: S2から「＋」でS4に遷移でき、入力欄が問題なく操作できる。

ステップ8: ローカル保存（localStorage）でのCRUD実装
- やること: S4で入力した内容を`localStorage`に保存し、S2に戻ったときにその保存データを一覧表示するようにする。編集・削除も同様に実装する。
- 完成の目安: アイテムを追加・編集・削除し、ブラウザをリロードしてもデータが保持されている。

ステップ9: S3買い物リスト画面の実装
- やること: 「買う」状態のアイテムだけを抽出して表示するチェックリストを作成する。チェックすると在庫状態が「在庫あり」に戻る処理を実装する。
- 完成の目安: S2で「買う」にしたアイテムがS3に表示され、チェックするとS2側の状態も「在庫あり」に変わる。

ステップ10: 「買い物終了」一括更新機能
- やること: S3にチェック済みアイテムをまとめて在庫ありへ反映する「買い物終了」ボタンを実装する。
- 完成の目安: 複数アイテムをチェックした状態でボタンを押すと、全て在庫ありに一括更新される。

ステップ11: S6カテゴリ管理画面の実装
- やること: カテゴリの追加・削除・並び替えができる画面を作り、`localStorage`のカテゴリ一覧に反映する。S2・S4のカテゴリ選択もここで管理された一覧を参照するようにする。
- 完成の目安: カテゴリを追加・削除すると、S2のタブとS4の選択肢に即座に反映される。

ステップ12: S5アイコン選択画面の静的UI（仮保存）
- やること: 「カメラで撮影」「写真から選択」ボタンを実装し、選択した画像をひとまずdata URLとしてS4のプレビューに反映する。
- 完成の目安: 画像を選ぶとS4のアイコンプレビューに反映され、保存後S2のアイテムカードにも表示される。

ステップ13: アイコンの使い回し機能
- やること: 一度選んだ画像を履歴として`localStorage`に保存し、S5の「登録済みアイコンから選ぶ」セクションに一覧表示・再選択できるようにする。
- 完成の目安: 過去に使ったアイコンがS5に一覧表示され、タップで再利用できる。

## 個人利用版の仕上げ

ステップ14: レスポンシブ・スタイル調整
- やること: スマホ表示を基準に全画面のレイアウト・余白・タップしやすさを整える。
- 完成の目安: 主要なスマホ画面幅で表示崩れがなく、ボタン類がストレスなく操作できる。

ステップ15: 個人利用での動作確認
- やること: 自分一人で使う一連の操作（アイテム登録・アイコン設定・カテゴリ管理・在庫切れ登録・買い物リストでのチェック・買い物終了）を通しで試し、不具合を洗い出す。
- 完成の目安: 想定シナリオ（買い物メモを手書きせず、スマホに登録→買い物当日にチェック）が最初から最後まで問題なく行える。

ステップ16: 公開（任意）
- やること: 個人で使うだけであればこのステップは必須ではないが、自分のスマホの実機から使いたい場合などは、静的ファイルをホスティングサービス（Firebase Hosting、GitHub Pagesなど。Firestore/Authenticationは使わないため無料枠で十分）に公開する。
- 完成の目安: 発行されたURLに自分のスマホからアクセスでき、これまでの機能が問題なく動作する。

## 家族共有を追加する時のステップ（保留中）

個人利用版が完成し、「家族と共有したい」となったタイミングで着手する。元のステップ14〜20の内容をそのまま保持している。

F-1: Firebaseプロジェクトの作成とSDK導入
- やること: Firebaseコンソールでプロジェクトを作成し、Authentication・Firestore・Storage・Hostingを有効化する。プロジェクトにFirebase SDKを組み込み、初期化コードを設置する。
- 完成の目安: コンソールにエラーが出ず、Firebase SDKの初期化が完了したとログ等で確認できる。

F-2: S1ログイン画面とFirebase Authenticationの実装
- やること: S1のログイン画面UIを作成し、Googleログイン等でFirebase Authenticationと接続する。未ログイン時はS1、ログイン済みならS2へ自動遷移する処理を実装する。
- 完成の目安: ログインボタンを押すとログインでき、ログイン後は自動でホーム画面に移動する。

F-3: 家族グループの作成・招待コード参加機能
- やること: S1の分岐カード（グループ作成／招待コードで参加）を実装し、Firestoreに`families`ドキュメントを作成・参加する処理を実装する。
- 完成の目安: 新規グループを作成すると招待コードが発行され、別アカウントでそのコードを入力すると同じグループに参加できる。

F-4: アイテム・カテゴリデータのFirestore移行
- やること: これまで`localStorage`で行っていたアイテム・カテゴリのCRUDを、Firestoreの`families/{familyId}/items`・`categories`に置き換える。個人利用版のローカルデータを初回ログイン時に家族グループへ取り込む移行処理も合わせて実装する。
- 完成の目安: アイテム・カテゴリの追加・編集・削除がFirestore上に反映され、Firebaseコンソールでデータが確認できる。

F-5: リアルタイム同期の実装
- やること: Firestoreの`onSnapshot`を使い、他のメンバーが更新したデータが即座にS2・S3に反映されるようにする。
- 完成の目安: 2つのブラウザ（または端末）で同じ家族グループを開き、片方での変更がもう片方に自動で反映される。

F-6: Firebase Storageへのアイコン画像アップロード
- やること: S5で選択した画像をFirebase Storageにアップロードし、そのURLをFirestoreのアイテム／アイコン履歴に保存するよう変更する（個人利用版のdata URL方式から切り替え）。
- 完成の目安: アップロードした画像が別端末からも正しく表示され、使い回しもFirestore経由で機能する。

F-7: S7家族・設定画面の実装
- やること: 家族グループ名・招待コード表示、メンバー一覧、カテゴリ管理への導線、ログアウトボタンを実装する。
- 完成の目安: 招待コードが確認でき、ログアウトするとS1に戻る。

F-8: 家族間での動作確認（複数アカウントテスト）
- やること: 実際に家族役の複数アカウントで一連の操作（登録・在庫切れ登録・買い物・カテゴリ変更）を通しで試し、不具合を洗い出す。
- 完成の目安: 想定シナリオ（口頭で頼まず自分で登録→買い物当日にチェック）が最初から最後まで問題なく行える。

F-9: Firebase Hostingへのデプロイ
- やること: `firebase deploy`等でアプリを本番環境に公開し、スマホのブラウザ（またはホーム画面追加）から実際にアクセスできるようにする。
- 完成の目安: 発行されたURLに家族全員のスマホからアクセスでき、これまでの機能が本番環境でも動作する。
