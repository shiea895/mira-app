# 買い物リスト共有アプリ 仕様書（第2版）

> **第2版での変更点**：開発初期は「個人利用」に範囲を絞り、家族共有（ログイン・Firebase連携）は後から追加できる形で将来対応とする。データの保存先（`localStorage`）を後でクラウド（Firestore）に差し替えやすいよう、保存処理を関数単位で分離して実装している。将来対応の詳細は[5. 今後の拡張: 家族共有版](#5-今後の拡張-家族共有版)を参照。

## 0. 概要

### 背景・課題
- 口頭で頼まれた買い物を忘れる
- 手書きメモに漏れが発生する
- 結果として「買い忘れ」「在庫切れの放置」が起きる

### ターゲットユーザー
- **現在のフェーズ**：自分自身（個人利用）
- **将来的に**：家族（複数人でデータを共有する）→ 第5章で後日追加

### 解決の方針（個人利用フェーズ）
- 在庫が切れた瞬間にスマホで記録し、買い物当日にメモ漏れを防ぐ
- 登録済みのデータは端末（ブラウザ）に保存し、いつでも参照・編集できるようにする
- 家族との共有は将来のフェーズで追加する（現時点ではスコープ外）

### 最低限必要な機能（個人利用版）
| # | 機能 | 内容 | 状況 |
|---|------|------|------|
| 1 | カテゴリ分け | 「日用品」「食品」などでアイテムをソート・絞り込み | 実装済み |
| 2 | アイコン画像 | カメラ撮影 or 画像選択でアイコン登録、以降は使い回し可能 | 実装済み |
| 3 | データ保存 | 登録した品目・状態を永続保存 | 実装済み（`localStorage`） |
| 4 | 家族共有 | 同じデータを家族間でリアルタイム共有 | **将来対応**（第5章） |

## 2. 各画面の役割とUI要素

### S1. ログイン / 家族グループ選択画面 【将来対応】
**役割**：誰のデータか（どの家族グループか）を確定させる、アプリ利用の入口。

> 個人利用版では未実装。家族共有を追加するタイミング（第5章）で実装する。

**UI要素**
- ロゴ／アプリ名
- ログインボタン（Googleログイン等、後述の技術選定に合わせる）
- 初回ログイン後の分岐カード
  - 「新しく家族グループを作る」ボタン → グループ名入力 → 招待コード発行
  - 「招待コードで参加する」ボタン → コード入力欄 → 参加確定

**遷移**
- ログイン＆グループ確定 → S2（ホーム画面）

---

### S2. ホーム画面（在庫リスト）※メイン画面
**役割**：登録済みの全アイテムを見渡し、在庫状況を確認・更新する。

**UI要素**
- ヘッダー：アプリ名、設定アイコン（個人利用版では未実装のS7への仮の導線）
- カテゴリタブ／フィルターチップ（例：すべて／食品／日用品／その他）（→カテゴリ管理はS6）
- アイテムカード一覧（カテゴリごとに見出し区切り）
  - アイコン画像（サムネイル）
  - アイテム名
  - 在庫状態バッジ（「在庫あり」／「在庫切れ・要購入」）
  - タップで在庫状態をワンタップ切替（在庫あり ⇔ 買う）
  - 長押し／編集アイコンでS4へ
- フローティングアクションボタン「＋」→ S4（新規登録）
- 下部ナビゲーション：ホーム(S2) / 買い物リスト(S3) / 設定(S7)

**遷移**
- ＋ボタン → S4（新規追加モード）
- アイテムの編集アイコン → S4（編集モード）
- 下部ナビ「買い物リスト」→ S3
- 設定アイコン → S7

---

### S3. 買い物リスト画面
**役割**：買い物当日に持ち歩き、「買う」フラグの立ったアイテムだけをチェックしながら購入する。

**UI要素**
- ヘッダー：「買い物リスト」タイトル、購入予定件数
- カテゴリ別グルーピングされたチェックリスト
  - チェックボックス（購入完了マーク）
  - アイコン、アイテム名
  - チェックすると在庫状態が自動で「在庫あり」に戻る
- 「すべて完了」または「買い物終了」ボタン（チェック済みアイテムを一括で在庫ありに反映）
- 下部ナビゲーション（S2と共通）

**遷移**
- 下部ナビ「ホーム」→ S2
- 特に無ければそのまま利用（買い物中に離脱しても状態は保持）

---

### S4. アイテム登録・編集画面
**役割**：アイテムの新規登録・既存情報の編集を行う。

**UI要素**
- ヘッダー：「アイテムを追加」／「アイテムを編集」、保存ボタン、（編集時）削除ボタン
- アイコンプレビュー（タップ → S5 アイコン選択画面へ）
- アイテム名入力欄
- カテゴリ選択（ドロップダウン／チップ選択、S6で管理されたカテゴリ一覧から選ぶ）
- 在庫状態トグル（在庫あり／買う）
- メモ欄（任意、例：「〇〇スーパーの安いやつ」等の補足）
- 保存ボタン／キャンセルボタン

**遷移**
- アイコンタップ → S5（アイコン選択）→ 選択完了で本画面に戻る
- 保存 → S2へ戻る（データはリアルタイムでS2/S3に反映）
- キャンセル／戻る → 直前の画面へ

---

### S5. アイコン選択画面
**役割**：アイテムの見た目（アイコン画像）を設定する。一度登録した画像は使い回せるようにする。

**UI要素**
- 「カメラで撮影」ボタン
- 「写真から選択」ボタン
- 「登録済みアイコンから選ぶ」セクション（過去に使ったアイコンをサムネイル一覧表示、タップで選択）
- プレビュー＆「決定」ボタン

**遷移**
- 決定 → S4に戻り、選択した画像がプレビューに反映される

---

### S6. カテゴリ管理画面
**役割**：カテゴリ（食品／日用品など）を家族で共通管理する。

**UI要素**
- カテゴリ一覧（ドラッグで並び替え可能、リストの右にゴミ箱アイコン）
- 「＋カテゴリを追加」入力欄・ボタン
- 各カテゴリの色・アイコン（任意、絞り込みタブの視認性向上のため）

**遷移**
- S7（設定画面）またはS2のカテゴリタブ横の管理ボタンから遷移
- 保存／戻る → 呼び出し元の画面へ戻る

---

### S7. 家族・設定画面 【将来対応】
**役割**：家族共有の管理とアプリ全体設定。

**UI要素**

## 4. 使用する技術（個人利用版）

### フロントエンド
- **HTML / CSS / JavaScript**（フレームワーク無し）で実装
- モバイル利用が前提のため、レスポンシブ対応（CSS Flexbox / Grid、スマホファーストのブレークポイント）
- 将来的な機能拡張・保守性を考え、素のJSが複雑になってきた場合は軽量フレームワーク（例：React または Vue）への移行も検討可
- PWA化（ホーム画面追加、オフライン時の簡易キャッシュ）は将来検討事項とし、初版では必須要件としない

### データ保存
- **`localStorage`**：アイテム・カテゴリ・アイコン履歴をこの端末のブラウザ内に永続保存
- バックエンド（サーバー・クラウドDB）は個人利用版では導入しない
- 保存処理は`loadItems`/`saveItems`のように読み込み・書き込みを関数単位で分離して実装しており、将来クラウド保存（Firestore等）に差し替える際もUI側のコードを大きく変えずに済む設計にしている

### 想定データ構造（個人利用版・`localStorage`）
```
localStorage["mira-app:items"]
  [{ id, name, category, status("in_stock" | "need_to_buy"), memo, iconUrl }, ...]

localStorage["mira-app:categories"]
  [{ id, name, color }, ...]

localStorage["mira-app:icon-history"]
  [{ id, url, createdAt }, ...]   // 使い回し用アイコン画像の履歴（data URL）
```

## 5. 今後の拡張: 家族共有版

個人利用版が完成した後、「家族と共有したい」となった時点で追加する内容。個人利用版の作りを壊さず、以下を**追加**する形で対応する。

### 追加する画面
- S1 ログイン / 家族グループ選択画面
- S7 家族・設定画面

### バックエンド導入
家族間のリアルタイム共有と画像保存のため、以下を想定：
- **Firebase Authentication**：ログイン機能（Googleログイン等）
- **Cloud Firestore**：アイテム／カテゴリ／家族グループのデータ保存、リアルタイム同期
- **Firebase Storage**：アイコン画像の保存
- **Firebase Hosting**：Webアプリのホスティング

※自前サーバーを持たずに「保存」「共有」「画像アップロード」を最短で実現できる構成として提案。要件やコスト方針次第で他の構成（自前API＋DBなど）に変更可能。

### 想定データ構造（家族共有版・Firestore）
```
families/{familyId}
  name, inviteCode, members[]

families/{familyId}/categories/{categoryId}
  name, order, color

families/{familyId}/items/{itemId}
  name, categoryId, iconUrl, status("in_stock" | "need_to_buy"),
  memo, updatedAt, updatedBy

families/{familyId}/icons/{iconId}   // 使い回し用アイコン画像の履歴
  imageUrl, createdAt
```

### 個人利用版からの移行で必要になる作業
1. **既存データの引き継ぎ**：`localStorage`にある個人利用版のデータを、初回ログイン時に家族グループへ取り込む処理
2. **アイコン画像の持たせ方の変更**：現在はdata URLとしてそのまま保存しているアイコン画像を、Firebase Storageへのアップロード＋URL参照の形に変更

- 権限管理（誰でも編集可 or 管理者のみカテゴリ編集可）は運用しながら判断
